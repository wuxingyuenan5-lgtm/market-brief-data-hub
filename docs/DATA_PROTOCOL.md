# 统一数据获取与报告协议

本协议适用于“每日跨资产交易晨报 V4”和“纯国内交易晨报”。

## 1. 执行顺序

每次生成报告前按以下顺序读取配置：

1. `vendor/upstreams.lock.yaml`
2. `config/shared/data_contract.yaml`
3. `config/shared/sources.yaml`
4. `config/shared/routing.yaml`
5. `config/shared/quality_rules.yaml`
6. `config/shared/instruments.yaml`
7. 对应报告的 `report.yaml`

若配置冲突，优先级为：数据契约 > 质量规则 > 路由 > 报告配置。

## 2. 上游工具包

优先参考固定 commit 的：

- `simonlin1212/a-stock-data`
- `simonlin1212/global-stock-data`

“参考”包括端点路由、代码归一化、真实取数验活、限流、缓存、静默失败识别和备源降级。除非运行环境实际执行了对应代码，否则报告不得声称“已通过该工具包取得数据”。

## 3. 主源与备源

每个数据集必须定义主源和备源。备源应尽量满足：

- 不同域名；
- 不同风控系统；
- 不依赖同一底层接口；
- 能核对标的、日期、单位和价格。

主源失败不等于数据缺失。必须先验证请求参数和代码映射，再尝试备源。

## 4. 真实取数验活

HTTP 200、非空 JSON 或非空 DataFrame 都不能直接证明数据有效。至少检查：

- 标的名称是否匹配；
- 市场和交易所是否匹配；
- 交易日期是否为最近有效交易日；
- 时间戳是否推进；
- 成交量是否合理，停牌需有明确标记；
- OHLC是否满足基本关系；
- 价格是否处于合理范围；
- 是否存在旧代码、僵尸报价或过期缓存；
- 空数组是否由接口错误、参数错误或权限限制造成。

## 5. 标的归一化

- A股代码必须显式解析交易所和资产类别。
- `000001`、`000016`、`000300`等歧义代码不得只凭数字猜测。
- 北交所旧号段不得直接作为当前代码使用。
- 港股统一为5位代码。
- 美股保留点号、横杠等特殊映射。
- 期货必须注明合约月份或明确的主力合约口径。
- 指数不得用ETF替代后写入“最新值”。

## 6. 时点与口径

每个关键数字都应保存：

- 市场时点；
- 抓取时点；
- 市场本地日期；
- 北京时间；
- 单位和币种；
- 统计口径；
- 数据源；
- 质量状态。

不得把不同市场的最近有效时点伪装成同一时间快照。

## 7. 数据冲突

冲突处理顺序：

1. 官方、监管、交易所；
2. 公司正式披露；
3. 一线数据商；
4. 成熟行情门户；
5. 权威媒体；
6. 研究机构与专业评论。

若冲突来自口径不同，应同时保留并说明差异，不取平均值。

## 8. 缓存

缓存必须包含：

- 生成时间；
- 数据源；
- 市场交易日；
- 标的；
- 数据集；
- 配置版本。

过期缓存不得进入“最新值”列。历史研究可使用旧缓存，但必须显示准确日期。

## 9. 宏观数据

宏观数据尽量包含：

- Actual；
- Consensus；
- Previous；
- Revision；
- 统计期；
- 发布时间；
- 市场反应。

不得混用环比、同比、年化、季调和未季调口径。

## 10. 派生数据与图表

价差、基差、收益率曲线、技术指标和图表应由已验证的原始数据本地计算，并记录：

- 公式；
- 输入数据；
- 时点；
- 缺失值处理；
- 数据源血缘。

没有可靠输入时不生成图表。

## 11. 缺失值

主备源都失败后统一写：

> 未取得同一时点可核验数据

可以在研究备注中列最近可靠历史值，但必须注明日期，且不得放入“最新值”列。

## 12. 合规与安全

- 官方公开数据优先。
- 受限数据仅用于个人研究，不批量再分发原始数据库。
- 公开仓库不得提交API密钥、Cookie、SEC联系邮箱、代理地址或账户信息。
- 敏感配置通过本地环境变量或GitHub Secrets提供。

## 13. 报告质量闸门

进入标题、90秒决策区、市场地图和图表的数字，原则上应为：

- `official_verified`；或
- `cross_source_consistent`。

单源行业数据可以使用，但必须标注 `single_source_pending`。疑似陈旧数据必须排除。
