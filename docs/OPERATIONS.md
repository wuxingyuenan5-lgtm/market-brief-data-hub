# 晨报配置与运行操作手册

本手册适用于《跨资产交易晨报 V4》和《纯国内交易晨报》，用于规范配置读取、数据执行、仓库修改、版本升级、故障披露和报告交付。

## 1. 每次运行前的强制读取顺序

每次生成晨报前，必须读取 `main` 分支以下文件：

1. `vendor/upstreams.lock.yaml`
2. `config/shared/data_contract.yaml`
3. `config/shared/sources.yaml`
4. `config/shared/routing.yaml`
5. `config/shared/quality_rules.yaml`
6. `config/shared/instruments.yaml`
7. 对应报告的 `report.yaml`
8. `docs/DATA_PROTOCOL.md`
9. `docs/OPERATIONS.md`

不得只读取 README 后推断配置。

任一必要文件无法读取时，报告必须原样披露：

> 共享配置仓库读取失败，本次按最后已知口径执行。

配置冲突优先级：

1. `config/shared/data_contract.yaml`
2. `config/shared/quality_rules.yaml`
3. `config/shared/routing.yaml`
4. `config/shared/instruments.yaml`
5. 对应报告的 `report.yaml`
6. 对应报告目录下其他专属配置

报告专属配置不得降低公共质量门槛。

## 2. 报告配置隔离

- 《跨资产交易晨报 V4》只使用 `config/cross_asset/` 下的专属配置。
- 《纯国内交易晨报》只使用 `config/domestic/` 下的专属配置。
- 不得使用一份晨报的 `report.yaml` 覆盖另一份晨报。
- 共同使用的数据源、字段、单位、代码映射、质量状态和缺失值规则，应在 `config/shared/` 中维护。
- 修改公共配置前，必须说明对两份晨报的影响。

## 3. 上游工具锁定与升级

上游项目必须以 `vendor/upstreams.lock.yaml` 中的 commit 为准，不得自动跟随上游 `main`。

读取顺序：

1. 读取锁文件；
2. 读取锁定 commit 的 `SKILL.md`；
3. 检查当前任务所需端点、字段、限流、验活与降级逻辑；
4. 只有实际执行代码后，才能声称已使用该端点取得数据。

发现新版本时只能：

1. 记录版本与 commit；
2. 阅读变更日志；
3. 检查字段、单位、接口、合规与静默失败修复；
4. 运行回归测试；
5. 向用户报告影响；
6. 经确认后更新锁文件。

## 4. 单次报告运行流程

### 4.1 建立运行上下文

记录：

- 报告 ID；
- 报告日期；
- 北京时间开始时间；
- 配置分支与 commit；
- 上游锁定 commit；
- 交易日状态；
- 数据截止时间。

### 4.2 执行数据路由

每个数据集按 `config/shared/routing.yaml`：

1. 标的归一化；
2. 主源请求；
3. 载荷结构与标的身份校验；
4. 交易日和时间戳校验；
5. 价格、OHLC、成交量和单位校验；
6. 僵尸报价与缓存检测；
7. 独立备源交叉验证；
8. 质量状态分配；
9. 保存来源血缘和失败记录。

主源失败后才能切换备源。不得静默使用过期缓存。

### 4.3 数据质量闸门

以下位置原则上只接受：

- `official_verified`
- `cross_source_consistent`

适用位置：

- 标题关键数字；
- 90秒决策区；
- 市场地图最新值；
- 图表输入；
- 宏观 Actual；
- 资金流头条。

`single_source_pending` 仅可在公共规则允许的专业数据中使用，并必须披露。

`suspected_stale` 必须排除。

`unavailable` 统一显示：

> 未取得同一时点可核验数据

### 4.4 派生指标

基差、月差、收益率变化、技术指标、资金聚合和图表必须基于已验证原始数据本地计算，并保存：

- 输入数据与来源；
- 输入时点；
- 公式；
- 统计周期；
- 缺失值处理；
- 输出单位；
- 质量状态。

### 4.5 报告生成

报告必须：

- 使用对应报告专属格式配置；
- 保留数据截止时间；
- 区分事实、短期定价、长期基本面、推断和待验证假设；
- 同时生成聊天摘要和自包含 HTML；
- HTML不得依赖CDN、外部字体或远程图片；
- 文件名符合报告配置；
- 输出前完成来源与数据口径检查。

## 5. 失败与降级披露

必须区分：

- 配置文件读取失败；
- 上游代码无法读取；
- 依赖未安装；
- 数据源网络不可达；
- 数据源限流；
- 参数或代码映射错误；
- 载荷结构变化；
- 标的确实无数据；
- 数据尚未发布；
- 非交易日。

不得将接口错误、空数组、旧缓存或错误标的描述为“市场没有数据”。

未实际完成时，不得声称：

- 已安装上游项目；
- 已执行某个接口；
- 已完成跨源验证；
- 已使用代理或秘密配置；
- 已更新缓存。

## 6. 仓库修改权限

### 6.1 报告专属配置

可以维护：

- `config/domestic/**`
- `config/cross_asset/**`

但只能修改当前负责报告对应的目录。

国内晨报不得修改 `config/cross_asset/**`。

跨资产晨报不得修改 `config/domestic/**`。

### 6.2 公共配置

默认不得直接修改：

- `config/shared/data_contract.yaml`
- `config/shared/sources.yaml`
- `config/shared/routing.yaml`
- `config/shared/quality_rules.yaml`
- `config/shared/instruments.yaml`
- `vendor/upstreams.lock.yaml`

需要修改时，先说明：

1. 当前问题；
2. 建议修改；
3. 对国内晨报的影响；
4. 对跨资产晨报的影响；
5. 是否需要升级上游锁定版本。

用户确认后，通过独立分支和 Pull Request 提交。

## 7. 分支、提交与Pull Request

较大修改使用独立分支。建议命名：

- `domestic-config/<topic>`
- `cross-asset-config/<topic>`
- `shared-data/<topic>`
- `ops/<topic>`

提交前检查：

1. YAML可解析；
2. 字段名符合公共契约；
3. 无真实密钥、Cookie、Token、邮箱或代理地址；
4. 未降低公共质量门槛；
5. 未修改另一份晨报的专属配置；
6. 兼容性和迁移说明完整。

Pull Request必须说明：

- 修改文件；
- 修改原因；
- 对两份晨报的影响；
- 是否涉及上游版本；
- 回滚方式；
- 验证结果。

## 8. 敏感信息

本仓库为公开仓库。所有分支和提交都可能公开。

不得提交：

- API密钥；
- Token；
- Cookie；
- 个人邮箱；
- 代理地址；
- 账户信息；
- 其他秘密。

敏感信息只能放在：

- 运行环境变量；
- GitHub Actions Secrets；
- 本地未提交的 `.env`；
- 用户明确授权的秘密管理工具。

仓库只允许保留 `.env.example`。

## 9. 缓存操作

缓存键至少包括：

- 数据集；
- 归一化代码；
- 周期；
- 市场时间戳。

缓存元数据至少包括：

- 生成时间；
- 来源；
- 交易日期；
- Schema版本；
- 配置commit。

过期缓存不能进入“最新值”列。缓存冲突时不取平均，应保留来源差异。

## 10. 运行后检查

报告输出后检查：

1. 必读配置是否全部成功读取；
2. 锁定上游版本是否一致；
3. 所有关键值是否有来源、时点、单位和质量状态；
4. 不同交易日和时区是否被错误对齐；
5. 市场地图是否包含规定资产；
6. 图表是否只使用验证数据；
7. 缺失值是否使用统一文本；
8. 研究账本是否标记新增、强化、弱化、被证伪或暂无新增证据；
9. HTML是否可离线打开、移动端可读、可打印；
10. 是否误改另一份晨报的专属配置。
